# 商品图 × 商家模板图片合成

一个面向外卖海报的 Python 图片合成工具。它会把商品图和商家模板合成为一张竖版海报，并尽量保持模板中的品牌信息、活动文案和底部规则说明。

项目提供两种合成策略：

- `overlay`：优先使用 PNG 模板原生透明通道，仅将 Logo、图案和活动文字叠加到铺满画布的商品图上；没有透明通道时才去除与画布边缘连通的黑色、白色或浅色底。商品图始终按比例 cover，不拉伸变形。
- `cutout`：自动识别绿布/绿幕或大块白色、浅色占位区，直接将商品原图按占位区尺寸等比嵌入，不对商品图做模糊或二次主体叠加；没有可识别占位区时才使用 `rembg` 自动抠出商品并居中合成。
- `template_replace`（前端名称“模板替换”）：无需上传商品图，识别模板中的透明图片区、白色/绿色占位区或已有矩形商品照片，并将商品区域清除为绿色占位区；Logo、活动文案、背景、边框和输出尺寸保持不变。生成的模板可以直接交给 `cutout` 模式继续放入自己的商品图。
- `auto`（默认）：优先尊重模板的原生透明通道；没有 alpha 时再检测商品占位区，并在模板叠加和主体抠图之间判断。

绿幕检测会结合形状与占位区本身的颜色，区分绿色背景和装饰，并清理边缘附近的压缩绿边。如果有多个难以区分的绿幕，页面会提示手动指定；可单独添加该模板，在“主体抠图合成”中手动框选需要放置商品图的矩形范围。

## 安装

建议使用 Python 3.10+：

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
```

`rembg` 只在 `cutout` 模式没有检测到商品占位区时使用；按上面的 `requirements.txt` 安装即可。它默认使用轻量的 `u2netp` 模型（首次运行约下载 4.6 MB），如果不安装它，程序会自动使用 OpenCV GrabCut 作为兜底。

## 命令行用法

合成一张海报：

```bash
python -m food_compositor \
  --products ./inputs/burger.png ./inputs/noodles.png \
  --template ./inputs/template.jpg \
  --output-dir ./outputs \
  --mode auto
```

常用参数：

```text
--mode auto|overlay|cutout|template_replace
                                合成策略，默认 auto；模板替换请使用 template_replace
--size 1080x1920                 输出尺寸，默认沿用模板尺寸
--logo-pill / --no-logo-pill     overlay 模式下保留左上角 Logo 白色胶囊
--outline 0..1                   为模板图形添加白色可读性描边，默认 0.78
--quality 1..100                 JPEG 质量，默认 100
```

也可以在 Python 中调用：

```python
from food_compositor import compose

compose(
    product_path="inputs/burger.png",  # template_replace 模式可传 None
    template_path="inputs/template.jpg",
    output_path="outputs/burger.jpg",
    mode="auto",
)
```

模板替换只抠掉模板里的商品图，不需要商品素材；生成的绿色区域可直接用于下一步主体抠图。单张模板可使用“手动框选商品区”；手动框选使用严格矩形边界，只清除框内像素，不再自动扩展、补全或精修到框外：

```python
compose(
    product_path=None,
    template_path="inputs/306.jpg",
    output_path="outputs/306_blank.jpg",
    mode="template_replace",
    size="1280x720",
)
```

## 设计要点

1. 商品图先按画布比例 `cover` 裁剪，避免拉伸食物形状。
2. PNG 模板优先使用原生 alpha 通道，透明区域不会参与合成；无 alpha 的 JPG 模板才通过边缘主背景色（黑/白/浅灰）连通区域转透明，保留抗锯齿边缘和文字内部封闭区域。商品图按比例 cover 铺满画布，不拉伸变形。
3. 主体抠图会识别绿布/绿幕和大块浅色占位区，只替换该区域；商品原图使用等比例高质量重采样，不变形、不额外模糊。模板中的 Logo、标题和规则文案保持原始清晰度。没有可识别占位区的模板才按照商品主体的 alpha 边界抠图，并生成接触阴影。
4. 原图不会被覆盖，输出目录只写入新的 JPG/PNG 文件。
5. JPG 输出严格保持所选画布尺寸，并通过 JPEG 质量和色度采样自适应压缩到 300KB 以下；优先保持 4:4:4 和高质量，进入 4:2:0 时优先保留亮度细节（文字、描边和食物纹理），输出阶段不会改变宽高或拉伸商品图。

## 运行示例

把自己的商品图和模板图放在 `inputs/` 后运行：

```bash
python -m food_compositor \
  --products \
  ./inputs/burger.png \
  ./inputs/noodles.png \
  --template ./inputs/template.jpg \
  --output-dir ./outputs --mode auto
```

## React 前端工作台

项目现在包含一个 React + Vite 前端和 FastAPI 接口。启动后可以拖入商品图、模板图，选择合成方式，查看成品并下载 JPG。

默认的智能判断会分别识别每张模板并选择主体抠图或模板叠加；如识别不符合预期，可以在模板列表为该模板指定方式。主体抠图合成、模板叠加和智能判断支持多张模板和多张商品图：每张模板依次与全部商品图合成，完成一张模板后再处理下一张。模板可以多次添加或从模板库一次多选；页面会显示处理顺序，结果和 ZIP 文件按模板、商品顺序排列。单个组合失败时，其余结果仍可下载，页面会标明失败的模板和商品。模板替换模式依次处理所有模板，为每张生成空白模板；该模式不使用商品图，多张模板使用自动识别商品区。

### 合成空间站

登录后打开「合成空间站」，所有账号都能跨设备查看、下载、移入回收站和恢复共享成品。下载单图或 ZIP 时，对应成品会归档。登录前仅展示当前浏览器自己的记录。登录后，OSS 中仍在保留期内的旧记录也会自动出现在团队目录中。模板库由所有账号共用。

在「合成记录」搜索制作账号（例如 `zs`），点击匹配的作品集，或输入完整账号后按回车。作品集按北京时间列出日期，同日按批次最近入库时间倒序排列。搜索复用已加载的批次目录。已有账号文件夹会自动归类，缺少制作账号的旧批次仍可在「全部合成记录」里找到。

以账号 `zs` 提交的任务为例，图片按合成提交时的北京时间和成品尺寸命名为 `20261123-zs-竖版-（1）.jpg` 或 `20261123-zs-横板-（1）.jpg`。正方形记作「方版」。每个批次内，各版式按模板和商品的添加顺序独立编号。首次下载或移入回收站时，按当时的北京时间为该账号分配批次文件夹，例如 `2026-11-23-zs（1）`。同账号同日的新批次依次递增，重复下载、恢复或由其他账号下载已归档的图片均沿用已分配的名字。

空间站复用已有 OSS 桶和凭证，默认使用 `picture-workflow/compositions/`。可通过 `OSS_COMPOSITION_PREFIX`（也可写入 `runtime/local-oss.json`）指定独立目录。OSS 凭证需能列举桶内此前缀，并读取、写入和删除此前缀的对象。建议将空间站放在私有桶内；有版本控制或额外留存规则的桶，历史对象版本由桶的生命周期规则管理。

每条记录从下载入库或移入回收站起保留 7 天。到期后接口不再提供访问，服务启动时和此后每 15 分钟清理一次过期对象及已完成的临时批次。下载和移入回收站需要 OSS 可用，归档失败时页面会提供错误信息，原结果仍可预览。

空间站在服务器本地保存目录元数据（默认位于 `runtime/archive-catalogs/`），服务重启后可复用。首次建立目录时后台读取 OSS，以后按 ETag 核对变化。归档、移入回收站和恢复会同时更新已有目录。服务端按访问范围和 7 天到期时间筛选记录，打开文件夹后按 20 张分页加载。

确认登录账号后，工作台会提前加载合成记录目录。浏览器保存目录，重新打开即可按账号搜索。最近一分钟已同步的目录会直接复用，更早的目录先显示并在后台更新。目录按每张素材的 7 天到期时间自动扣减数量，最后一张到期时移除文件夹。回收站首次打开时加载，之后也复用目录缓存。退出或切换账号会清除目录缓存，原图在打开文件夹时按需加载。

模板目录也使用 60 秒缓存，并将成功快照保存在忽略提交的 `runtime/template-catalog-cache.json`，服务重启时可复用；模板后台刷新失败时最多使用一小时内的成功快照。上传/删除会同步更新缓存，刷新中的旧请求会合并这些操作。手动点击模板库刷新按钮可以主动更新。模板清单仍采用独立 JSON，不依赖多个进程同时覆盖同一 OSS 索引。缩略图使用私有浏览器缓存一天，原模板缓存一小时。

OSS REST 连接的 ListObjectsV2 后续页会将 `continuation-token` 原始值加入 V1 签名，并单独对传输 URL 编码，避免模板数量超过一页后触发 `SignatureDoesNotMatch`。没有目录快照的首次建立索引可能需要等待；单个列表请求最多等待 12 秒，后台继续建立缓存，页面会有限次数自动重试。

### 任务资源与发布检查

上传解析和 ZIP 使用应用磁盘上的临时目录，默认 `runtime/upload-temp`，可通过 `COMPOSITION_TEMP_ROOT` 指定。服务启动时将 Python `tempfile` 默认目录指向该路径，并让就绪检查同时覆盖批次与临时目录。不要使用容量较小的 `/tmp` RAM 盘承载大批量文件；生产主机 `/tmp` 仅约 1.8 GB，会低于默认 2 GB 保护线。

资源参数通过服务环境变量配置（本次未增加登录或访问口令）。默认每批最多 1,000 张商品图、1,000 张模板、10,000 张输出，总图片文件大小不超过 8,192 MB；单文件不超过 200 MB。组合数按商品图数乘模板图数计算（模板替换只计算模板数），各上限须同时满足。输出最长边不超过 4096 像素、总像素不超过 800 万；商品图去重仍要求解码像素不超过 2,400 万。可设置 `MAX_BATCH_PRODUCTS`、`MAX_BATCH_TEMPLATES`、`MAX_BATCH_OUTPUTS`、`MAX_BATCH_UPLOAD_MB`、`MAX_UPLOAD_MB` 调整限制。批量解析器同步放宽文件总数，避免 1,000 张商品加模板触发框架默认限制。结果每页预览 60 张，后台进度只返回摘要，完成后返回全量元数据；全选跨页生效。下载选中项通过 POST JSON 传输 ID，避免大批次 URL 过长。

提交接口在解析 multipart 前检查整体请求大小（额外预留 4 MB 表单开销，同时检查分块请求）；默认同来源 IP 最多 2 个在途任务、全服务最多 4 个在途任务、同来源每分钟 10 次提交，任务结束后释放名额。对应 `MAX_ACTIVE_TASKS_PER_CLIENT`、`MAX_ACTIVE_TASKS`、`MAX_TASKS_PER_MINUTE`。磁盘至少预留 2,048 MB（`MIN_FREE_DISK_MB`）：上传前按请求两倍大小检查输入目录和系统临时目录（multipart 临时副本和任务输入可能共存），上传接收、输入落盘、计算派发及 ZIP 逐文件写入时再次检查。空间不足返回 507 或停止任务后续派发，保留已完成结果，ZIP 失败会清理半成品；取消或任务结束后清理任务输入。8 GB 是配置上限，不代表任意时刻都有足够空间接收。Nginx 应设置 `client_max_body_size 9g`（包含表单开销）、`proxy_request_buffering off`；外部程序占盘和其他系统任务仍可能影响余量。实际图像计算由 CPU/内存进程池约束，不会随批量数无上限增加并发。反向代理只信任自己的代理地址；多 Uvicorn 主进程需改为共享限额存储，本版本按单服务进程部署。

`/api/health` 用于检查进程存活，`/api/ready` 检查前端构建和磁盘余量。发布后运行 `python tools/verify_service.py https://cwb.ainiankj.com --expected-asset <构建产出的JS文件名>`，检查健康、就绪状态、首页及全部 JS/CSS 资源是否一致。监控或部署脚本可根据非零退出码报警或停止切换版本。运维步骤见 [发布与恢复](docs/operations.md)。

GitHub Actions 会在推送和 PR 时运行前后端测试、构建并保存前端产物。前端依赖使用已验证的精确版本和 `npm ci`；`requirements-test.txt` 固定当前非推理测试环境的直接依赖，CI 使用 Python 3.11/3.13 和 Node 22。生产环境安装仍使用已有 requirements；可选 rembg 模型不由 CI 下载。云端告警、生产 Python 升级和自动部署需在对应服务器发布时配置。

## 工作台账号

在页面顶部点击「登录」→「注册账号」，以本人的英文缩写作为账号（例如张三使用 `zs`），自行设置并确认非空密码。点击输入框旁的「显示」可核对密码，再次点击「隐藏」即可遮住。账号接受 1–32 个英文字母，统一保存为小写。缩写重复时可以再加一个字母。注册成功后自动登录，所有账号拥有相同的共享空间权限。也可以在运行工作台的主机上创建账号或查看账号列表。

```bash
python -m tools.manage_accounts create zs
python -m tools.manage_accounts list
```

登录或注册时默认勾选「在此浏览器记住账号 30 天」。从上次使用密码登录或注册算起，30 天内再次打开工作台，如果需要登录，点顶部的「登录 zs」即可。每个浏览器记住最近一次选择记住的账号，使用公共电脑时可以取消勾选。「退出并保留快捷登录」结束当前会话，「退出并忘记此账号」同时移除本浏览器的快捷登录。浏览器保存的是凭证，工作台不会在本地保存密码。

在「我的账号」中点击「修改密码」，输入原密码并确认新密码。修改成功后，当前设备和其他设备的登录与快捷登录都立即失效。每台设备用新密码重新登录时，勾选「在此浏览器记住账号 30 天」即可重新启用快捷登录。

账号管理命令还支持 `reset-password`、`disable` 和 `enable`。重设密码或停用账号后，已有登录会话和所有浏览器的快捷登录立即失效。账号数据默认保存在同主机的 `runtime/accounts.sqlite3`，可通过 `WORKFLOW_ACCOUNTS_DB` 指定路径。正式环境通过 HTTPS 登录，本机回环地址可用于开发测试。

## 独立照片格式转换器

顶部「照片格式转换」打开独立工具，支持多选图片或文件夹，输出 JPG/JPEG 或 PNG。转换代码与任务目录独立于海报合成：不调用海报尺寸适配、占位区检测、描边、锐化或 300KB 压缩规则，不主动缩放、裁剪或旋转，保留所选图片/帧的解码尺寸和原有 EXIF 方向信息。原本已经是目标格式的单帧 JPG/PNG 直接复制，避免重复编码；跨格式转 JPEG 使用高质量 4:4:4 编码。JPEG 本身有损且不支持透明，透明部分使用白底；需要透明请选择 PNG。多帧 GIF/APNG/WebP 和多页 TIFF 等先识别帧数，用户逐张预览并选定帧/页后再导出静态图片，不自动取第一帧。

新接口独立位于 `/api/converter/`，包含能力查询、任务预留、上传、帧预览、开始转换、进度、取消、单图与 ZIP 下载。图片按真实内容解码，不依赖扩展名，支持 JPEG、PNG、WebP、BMP、GIF、TIFF、ICO、JPEG2000 等。Web 依赖增加 `pillow-heif`（HEIC/HEIF）和 `pillow-avif-plugin`（AVIF，兼容内置 AVIF 无可用编解码器的 Pillow 构建）；请使用 `pip install -r requirements-web.txt` 更新环境。SVG、PDF、相机 RAW、损坏文件或依赖缺失时会逐项报错，不能承诺任意文件均可转换。

结果使用浏览器空间标识保护访问，存于 `runtime/conversions`（可用 `CONVERSION_JOB_ROOT` 指定独立目录），不会写入 OSS 模板库、合成记录或回收站。完成/失败/取消任务保留结果 7 天，输入在任务结束后清理；等待选帧的输入最多保留 24 小时，未上传的预留任务 1 小时后清理。沿用受控共享计算池、文件/批量体积限制与磁盘保护，转换单图最多 6,000 万像素；PNG 可能比原图更大，编码与 ZIP 写入时均检查磁盘空间。转换新增入口不改变现有合成算法和账号方案。

## 合成性能说明

单张与批量任务共用可复用的进程池，按 CPU、可用内存和图片尺寸限制并发。同一模板的识别和图层处理会在进程内复用；结果仍按模板及商品顺序输出。详情和服务器实测见 [性能记录](docs/performance.md)。

点击合成后，页面会立即显示上传状态：上传阶段按浏览器实际发送字节显示进度，随后显示服务器准备任务，再切换到按已处理图片数量计算的合成进度。单张与批量任务均使用此流程；未知总字节数和准备阶段显示等待动画。

进度区域提供「取消任务」，适用于全部合成方式。前端先通过 `POST /api/batches/reserve` 分配当前浏览器拥有的任务编号，再上传图片，因此上传和准备阶段也可以取消；上传请求会中止，并通过 `POST /api/batches/{id}/cancel` 持久记录取消。后台停止后续派发，排队等待资源可被取消，运行中的图片在图像处理/压缩安全检查点退出。界面在服务端确认 `cancelled` 后恢复操作，并保留取消前已完成的结果，继续支持下载和空间站归档。单次第三方原生运算或模型下载期间需等待该调用返回到检查点；取消不会终止共享进程池或影响其他任务。重复取消安全，已完成任务仍保持完成状态，其他浏览器无法取消本人的任务。

取消状态为 `cancelling → cancelled`。服务重启后保留取消标记，不会恢复已取消任务；未提交的上传预留在一小时后由后台清理，取消批次及已完成图片按原有七天规则清理。网络故障导致取消未确认时页面提供重试提示，不将其直接标记成已取消。旧客户端不提供预留编号时仍兼容原批量接口。

选择商品图时会自动按文件内容及浏览器解码后的完整画面去重，同批选择和多次追加均只保留第一次添加的图片，并保留添加顺序。文件名不同但内容相同的副本也会去除；不同画面不会因同名或同大小被去除。检测期间显示进度，完成后提示新增、去重和读取失败的数量。相似照片、裁剪图或压缩后像素发生变化的图片仍会分别保留。
